# v0.4.0 を採用すべきか — 実測に基づく判断

`report.md` の評価結果を受けて、`docs/PROMPT_CATALOG_V0.4.0_DRAFT.md` の各変更を「効くか / 効かないか / 新しい欠陥を持ち込むか」で切り分けた。
文章生成側（カタログ §2）は、証拠を固定した対照実験で実測した。質問生成側（§1）は今回の30セッションの実データから読み取った判断で、未検証の部分は明記する。

## 結論

| 変更 | 判断 |

| §2 最終文章の証拠制約 | **採用。効果は実測済み**（証拠逸脱 57.0% → 2.5%） |

## 1. 文章生成側の対照実験

証拠（初期断片＋6ターンのQ/A）を `batch-20260725-prompt-eval` の30セッションから固定し、**文章生成プロンプトだけ**を差し替えた対応のある比較。生成モデル・温度は現行と同じ `gpt-4o-mini` / 0.75。判定は `report.md` と同一ルーブリック・同一判定モデル `gpt-5.5`。

| 変種 | 総文数 | 証拠逸脱率 | 影響セッション | 平均文字数 | 逐語コピー率 | 情緒的結語 | 非想起→事実 | 条件外の匂い語 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| **A** 現行 v0.3.0 | 256 | **57.0%** | 30/30 | 287 | 27% | 12/30 | 5 | 4 |
| **B** v0.4.0 §2 原文 | 160 | **2.5%** | 1/30 | 158 | 86% | 0/30 | 1 | 0 |
| **C** B − ペルソナ ＋ 結語禁止 ＋ 文数上限 | 158 | **0.0%** | 0/30 | 148 | 90% | 0/30 | 0 | 0 |
| **D** C ＋ 書き直しの明示的許可 | 63 | 1.6% | 1/30 | 149 | **70%** | 0/30 | 0 | 0 |

逐語コピー率 = 文章の文字のうち、参加者回答からの8文字以上の連続一致に含まれる割合。

**v0.4.0 §2 は狙いどおり効く。** 証拠逸脱を 57.0% から 2.5% へ、条件外の匂い語混入を4件から0件へ落とす。`report.md` で最重要とした欠陥は、この変更で解消する。

## 2. ただし v0.4.0 §2 をそのまま入れると起きること

### 2.1 逐語コピーへの反転（86〜90%）

B・C は、文章の 9割近くが参加者回答の逐語コピーになる。実例（standard-birthday-cake）:

```
C: 誕生日に自宅でケーキを受け取った。玄関でケーキを受け取りました。家族三人が一緒にいました。
   夕食を食べた後、ろうそくを吹き消して、家族三人でケーキを分けて食べました。…
```

冒頭2文が重複し、断片の常体と回答の敬体が混在している。「各文は証拠から直接導ける」という制約が、証拠と文の 1対1 対応へ収束させ、回答の羅列になる。

これは研究上の判断が要る点である。従属変数は生成文章への読後反応（記憶様感・情景構成感・叙述鮮明性・感情再体験感、DEC-010/011）なので、文章が回答の羅列になると全条件で低評価に張り付き、条件差を検出できなくなる可能性がある。**逆に、羅列に近いほど「文章生成器は条件を跨いで一定の変換である」ことは強く言える。** どちらを取るかは測定設計の選択であって、プロンプトの巧拙ではない。

変種 D は、内容制約を保ったまま「複数の証拠を1文にまとめる」「時間順に並べ替える」「文体を統一する」「自分の言葉で言い直す」を明示的に許可したもの。逸脱 1.6% を保ちながらコピー率を 70% へ、文体混在を 15/30 → 5/30 へ下げる。

```
D: 誕生日の日、玄関でケーキを受け取りました。家族三人が一緒にいて、夕食を食べた後にろうそくを
   吹き消し、みんなでケーキを分けて食べました。ケーキを食べた後、特に何かをした記憶はありません。
```

ただし D は 1セッション平均 2.1文（C は 5.3文）まで統合が進む。文数の下限を撤廃した効果が強く出ている。**D をそのまま採用するのではなく、「証拠制約は C、編集許可は D」の組み合わせを次の候補にすべき。** D のプロンプト全文は `variant-d.mjs` にある。

### 2.2 長さの交絡が新しく生まれる

| 変種 | standard | non-odor | odor-based | 最大/最小 |
|---|---:|---:|---:|---:|
| A 現行 | 274 | 306 | 280 | **1.12倍** |
| B v0.4.0 | 132 | 198 | 145 | **1.51倍** |
| C | 122 | 182 | 140 | 1.48倍 |
| D | 134 | 182 | 130 | 1.40倍 |

現行の8文下限は、条件間の文章長をほぼ揃えていた。ただしそれは**証拠の少ない条件を作話で埋めることで揃えていた**。下限を外すと文章長は証拠量に連動し（証拠量との相関 r = 0.22 → 0.67）、条件間で 1.4〜1.5倍の差が出る。

文章の長さは情景構成感・叙述鮮明性の評定に直接効く。**作話による交絡を、長さによる交絡に置き換えただけになる危険がある。** これは文章生成プロンプトでは解けない。原因は質問生成側にある（次節）。

## 3. 質問生成側 — v0.4.0 §1 の評価

### 3.1 採用すべき部分

- **§1.4 ターン機能の共通化**: 実測で6ターン中5ターンの最頻機能が条件間で不一致（`report.md` §2.3）。条件間で変えるのは焦点だけにする方向は正しい。
- **§1.6 非想起分岐の対称化**: 現行は odor-based にしか分岐がない。standard / non-odor の参加者は想起できなくても6ターン同じ路線で問われ続ける。
- **§1.7 targetEvidenceId の出力**: 現行の正規表現検証器は、Standard に混入した感情・感覚質問9件を通してしまった（`report.md` §2.1）。「直前の回答のどの部分を指しているか」をモデルに申告させ、その文字列が実際に証拠へ存在するかをサーバーで検査する方が、語彙パターンの追加より根治に近い。
  - ただし `conditionFocus` の自己申告は検査に使えない。モデルは「standard」と申告しながら感情を尋ねられる。**検証に使えるのは、外形的に照合できる `targetEvidenceId` だけ**と考えるべき。

### 3.2 §1.5 固定文面骨子は DEC-029 と衝突する

§1.5 のターン2〜6は実質的に固定質問文である（「先ほど述べた対象について、ほかに覚えていることはありますか？」等）。DEC-025 の固定質問方式は指導教員の指示で DEC-029 の生成質問方式へ上書きされており、DEC-025 の note には「生成質問は初期記憶断片を入力として、より出来事に関連した記憶を聞き出せる質問にする」とある。§1.5 をそのまま入れると、実質的に DEC-025 へ戻ることになる。

**技術的な判断ではなく研究上の判断なので、指導教員の確認が要る。** 中間案は、質問文そのものは生成させたまま、ターンごとの機能と焦点を §1.4 で固定し、§1.7 の targetEvidenceId で対象を証拠へ縛る方式。

### 3.3 ターン5・6の共通化は、そのまま入れると欠陥を全条件へ広げる

これが今回いちばん重要な発見である。

Standard 条件の非想起率は 35.0%（60ターン中21）で、他条件の 15〜17% の倍以上ある。実質回答は 3.8/6（他条件 5.0/6）、実質証拠量は 117文字（non-odor 182、odor-based 166）。§2.2 の長さの交絡の原因はここにある。

その22件を招いた質問を見ると、原因が特定できる:

| ターン | 件数 | 実際の質問 |
|---:|---:|---|
| 1 | 4 | その公園に**行く前**、どんな準備や計画をしていましたか？ |
| 5 | 4 | その後、公園を**出た後**はどのように過ごしましたか？ |
| 6 | 5 | 昼食を食べ終えた**後**、どのようにその時間を締めくくりましたか？ |

**Standard だけが、想起されたエピソードの外側（開始前・終了後）を繰り返し尋ねている。** 参加者が提出したのは一文の記憶断片であり、その前後は想起の対象外なので「思い出せません」になる。non-odor / odor-based はエピソードの内側（見えたもの・音・匂い）を尋ねるので、この問題が起きない。

v0.4.0 §1.4 の共通ターン機能は、この Standard のスケジュール（広い想起 → 深掘り → 時点 → 行動 → **終わりへの進行** → **最後の未解決な終わり**）をそのまま3条件へ適用する。§1.5 のターン5・6の骨子も「その後、出来事はどのように終わりへ進みましたか？」「その出来事の終わりに、あなたは何をしていましたか？」で、焦点に依存しない。

つまり v0.4.0 をそのまま入れると:

1. **Standard の証拠欠損は直らない**（原因のターン5・6をそのまま残すため）。
2. **同じ欠損を non-odor / odor-based へも広げる**（両条件のターン5・6が焦点から外れ、エピソード外を尋ねるようになる）。
3. **操作の投与量がさらに下がる**。odor-based が匂いを扱うのは既に 20/60ターンしかない（`report.md` §2.2）。ターン5・6が全条件共通の行動質問になると、焦点ターンは実質1〜4のみになる。

**推奨する代替**: ターン機能の共通化は行うが、「終わり」を機能から外し、6ターンすべてを割付焦点の内側に置く。例:

| ターン | 共通機能（焦点は条件別） |
|---:|---|
| 1 | 存在を前提にしない広い想起 |
| 2 | 直前の回答に明示された対象を1つ深掘り |
| 3 | その対象に気づいた出来事上の時点 |
| 4 | その時にしていた行動との関係 |
| 5 | 既出の**別の**対象を1つ深掘り |
| 6 | 既出の対象の未解決な属性を1つ深掘り |

これで (a) 機能は条件間で同一、(b) 6ターンすべてが焦点ターン、(c) エピソード外を尋ねない、の3つを同時に満たす。文章に「終わり」が要るという要件は無い（v0.4.0 §2.2 は結末の追加を禁止している）。

### 3.4 非想起分岐の判定はターン1限定のままではいけない

§1.6 は「ターン1で焦点対象を思い出せなかった場合」に限定している。現行実装も同じ（`hasNoOdorRecallAtTurnOne`、`app/api/question-validation.ts:81`）。実データでは、ターン2・5の非想起の直後に同じ焦点を再質問した例が3件あり、うち2件は匂いの存在を前提化していた（`report.md` §3）。**直前ターンの回答で判定するよう変更する。**

### 3.5 §1.3 non-odor → visual 単独は構成概念の変更

現行の non-odor は 6ターンで視覚→聴覚→触覚身体を各2ターン巡回する。§1.3 は視覚単独にする。対称性（odor 単一モダリティ vs non-odor 単一モダリティ）は改善するが、「Non-Odor＝匂い以外の感覚全般の統制条件」から「Visual＝視覚条件」へ条件の意味が変わる。DEC-029 は三条件を Standard / Non-Odor / Odor-Based で管理すると定めている。**指導教員の判断が必要で、プロンプト側で決めてよい事項ではない。**

## 4. 推奨する順序

1. **文章生成プロンプトを差し替える**（効果実測済み、最優先）。v0.4.0 §2 の内容制約を採用し、§2.1 の当事者ペルソナは外す。8文下限を撤廃する。編集許可（統合・並べ替え・文体統一・言い直し）と結語禁止を明示する。→ 変種 C の制約 ＋ 変種 D の編集許可。
2. **evidenceIds のサーバー側検査を実装する**（§2.3）。今回の30セッションでは不正IDも空IDも0件だったが、検査が無ければ保証にならない。
3. **非想起分岐を全条件へ用意し、判定を毎ターンへ広げる**（§1.6 ＋ 3.4）。
4. **ターン機能を共通化する。ただし 3.3 の代替スケジュールで**。ターン5・6を「終わり」から「焦点内の別対象の深掘り」へ変える。
5. **指導教員判断を仰ぐ2件**: §1.5 の固定骨子（DEC-029 との関係）、§1.3 の non-odor → visual（条件の構成概念）。
6. **検証器の正規表現の穴を塞ぐ**（`どのように感じ` など）。4 が入れば重要度は下がるが、独立した安全網として残す価値はある。

## 5. 次に測るべきこと

- **3.3 の代替スケジュールの効果**: 条件別の非想起率と実質証拠量が揃うか。今回と同じ30セッションを回して、standard 3.8/6・117文字 が non-odor / odor-based の水準へ近づくかを見る。長さの交絡（1.4〜1.5倍）が縮むかがゲート。
- **文章長と評定の関係**: 文章が半分の長さ（287→149文字）になったとき、記憶様感が測定可能なレンジに残るか。これは自動判定では答えられない。**小規模な人間パイロットでしか判断できない**（DEC-030 留保(4)と同じ）。文章プロンプトの凍結は、この確認の後にすべき。
- 今回の証拠逸脱率は `gpt-5.5` 単独のプロキシ判定で、人手検証も判定者間一致も取っていない。A と B/C/D の差（57% vs 0〜2.5%）は大きく、判定者の癖では説明しにくい水準だが、絶対値は保証しない。
