## 各項目の読み方

| フィールド | 取りうる値 | 意味 |
| --- | --- | --- |
| 状態 | `未着手` / `進行中` / `保留` / `完了` / `中止` | 終わったタスクは末尾の「完了・中止」節へ日付付きで移す。`完了`は決めた・作った、`中止`はやらないことにした。 |
| 優先度 | `最優先` / `高` / `中` | 同じ優先度内では上から処理する。 |
| 領域 | `研究設計` / `プロトコル` / `実装` / `運用・倫理` | 触る文書群。[decisions.md](decisions.md)の領域と同じ語を使う。 |
| 種類 | `決める` / `書く` / `実装` / `検証` / `承認をとる` | 作業の性質。`決める`は自分で判断できる、`承認をとる`は相手が要る。 |
| 関連 | DEC-xxx | 根拠になる決定。決定の中身は[decisions.md](decisions.md)で読む。 |
| 依存 | TASK-xxx / なし | 先に終わっている必要があるタスク。 |

**指導教員確認はタスクにしない**（DEC-040）。確認が必要だと判断したものだけ、その都度ここへ追加する。`種類: 承認をとる`は現在、倫理審査と所属機関の確認だけに使う。
