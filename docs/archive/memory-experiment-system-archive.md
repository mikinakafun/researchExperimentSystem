# memoryExperimentSystem 保全記録

作成日: 2026-07-22

## 保全対象の結論

`memoryExperimentSystem` は、研究プロトコルが確定する前に作られた実験システム候補である。判定は **NOT READY**。募集、人間パイロット、本番データ収集、公開配備には使わない。DEC-031 により機能追加を停止し、確定した `../protocol/PROTOCOL.md` を入力に最小構成で作り直す。

親プロジェクトの正本は `docs/MASTER.md`、`docs/project/decisions.md`、`docs/project/prototype-progress.md`。このファイルは削除した独立リポジトリの履歴・再利用判断・検証結果を一か所に集約した保全記録であり、今後の仕様の正本ではない。

## 研究プロトコル候補（すべて承認前の DRAFT）

- Standard / Non-Odor / Odor-Based の3条件、被験者間、日本語を先行。
- 初期想起断片は一文。追質問は6ターンをパイロット候補とする。
- Odor-Based の操作は実匂い刺激ではなく、質問の焦点。匂いを想起できない場合は中立的な出来事質問へ分岐。
- 生成文の証拠は初期断片・提示質問・参加者回答。未回答内容は証拠にしない。
- 生成文は記憶の正確な再構築とは説明しない。構造検証は意味的忠実性を保証しない。
- モデル、temperature、質問数、再試行、フォールバック、保存・削除期間は未承認。

## 次期最小構成へ残す設計原則

- APIキー、条件割付、内部プロンプト、棄却生成物はサーバー側だけに置く。
- 参加者画面には条件名、seed、内部識別子、割付情報を返さない。
- 通常検証は決定論的 mock。実API検証は明示許可された合成fixtureだけで行う。
- 一台運用なら単一 Next.js プロセス・単一 SQLite・単一 open run を前提にする。
- プロンプト版、モデル、temperature、質問・回答、生成試行を再現可能な形で記録する。
- 「自動テスト合格」と「心理実験として妥当」を別の判定として扱う。

## 反省と作り直し方針

失敗の中心はコード品質ではなく順序である。26件の未決定事項を抱えたまま、複数site、開始コード、割付、監査、export、backup、複数adapterまで実装したため、研究判断の変更が広いコード・テスト・fixture・文書へ波及した。次期版は次の縦一本を先に完成させる。

`開始 → 同意 → 一文入力 → 6質問 → 文章生成 → 評価 → SQLite保存 → 完了`

次期版の着手条件は、条件定義、質問数と役割、no-recall 分岐、文章の包含・除外規則、モデルと再試行、評価項目、保存期間・削除方法を一枚の `../protocol/PROTOCOL.md` として確定すること。管理者画面、遠隔運用、クラウドDB、複数site、参加者が扱う開始コード、汎用adapterは要件が実在するまで作らない。

## 検証結果と未解決リスク

- v0.3.0 dry run: 6 fragment × 3 condition × 6 turn、18会話・108質問、再試行2、fallback 1、最終flag 0、機械的IV gate PASS。ただし NOT FROZEN。
- 旧 v0.2.9 synthetic live run: 18/18質問、6/6文章、33外部リクエスト、機械的にはPASS。しかし日本語 Standard の文章に証拠にない「会話内容を覚えていなかった」という主張があり、人手の意味的レビューはFAIL。v0.3.0の検証結果ではない。
- 未解決: 状態遷移の非原子性、停止時に `processing` のまま残る idempotency、保持期間・暗号化・バックアップ復元、同意・倫理・API送信方針、モデルの意味的忠実性、アクセシビリティ、個人識別情報の自由記述対策。
