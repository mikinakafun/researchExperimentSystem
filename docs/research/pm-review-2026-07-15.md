## 0. 現状整理

### 0.1 プロジェクトの目的

匂いに注意を向ける質問設計が、参加者から引き出される記憶断片と、そこからLLMが生成した物語文章に対する本人の主観評価（情景構築感・鮮明さ・感情的雰囲気・記憶らしさ）を変化させるかを、三条件被験者間実験で検証する。実匂い刺激は使わず、対話設計の効果に限定する。大学院ではガスセンサと機械学習を用いた嗅覚インタラクションへの発展を構想している。

### 0.2 主要な決定事項

- 実匂い刺激を使わず、匂いに着目した質問を操作とする（DEC-001）
- Standard / Non-Odor / Odor-Based の三条件、一人一条件の被験者間計画、ランダム割付（DEC-002, 003）
- 人間評価を主要な研究結果に含める（DEC-004）
- LLMは断片情報から物語文章を「生成」する。「再構築」表現は避ける（DEC-005）
- Manipulation Check実施、共通の初期想起トリガー設置（DEC-006, 007）
- 卒業研究と大学院発展案を分離する（DEC-008）
- 現行expTest1は技術デモ扱いで、本実験には使用しない（DEC-009)
- 中心評価セットは4項目（暫定、DEC-010）

### 0.3 未解決の課題

主要評価項目の統計的位置づけ（DEC-011）、三条件の質問全文（DEC-012, 013）、Manipulation Check項目（DEC-014）、初期想起トリガー（DEC-015)、参加者言語（DEC-016)、対象者・除外基準（DEC-017)、LLMモデル版・生成制約（DEC-018)、同意・倫理（DEC-019)、保存・匿名化（DEC-020)、分析法・サンプルサイズ・事前登録（DEC-021〜023)、正式題名（DEC-024)。加えて、`.env.example`に実形式のAPIキーが残存している疑い（失効確認の記録なし）。

### 0.4 現在のボトルネック

コードでも文書でもなく、**意思決定**である。独立変数の実体である質問文が、5月末に「最優先」と整理されてから約6週間、依然として存在しない。文書化・監査・移行作業は精緻だが、実験を前進させる確定事項はこの間ほとんど増えていない。

### 0.5 今後3か月の成功条件

10月中旬までに、(1) 三条件の質問全文と対応表が確定し、(2) 主要評価項目・仮説・分析計画・サンプルサイズが事前固定（可能なら事前登録）され、(3) 倫理・同意手続きがクリアされ、(4) 仕様準拠のシステムで内部テストと小規模パイロットが完了し、データ収集を開始できる状態にあること。

## 1. Executive Summary

方向性は健全だが、実行が意思決定層で止まっている。独立変数（質問文）が未確定のまま文書整備が先行し、実験の実体がまだ存在しない。統計設計の「Bで取ってからAへ」案は分析の恣意性そのものであり、即時撤回すべきだ。設計凍結を2週間以内に行えば2月提出は可能。現状のパターンを続ければ、11月に未検証システムで慌ててデータを取る結末になる。

## 2. Current State Analysis (SWOT)

### Strengths

- 研究質問の絞り込み過程が健全。テキスト統計比較という自明な研究から、人間評価中心の因果検証可能な設計へ正しく転換した。
- 意思決定記録・用語規律・引用管理の水準が学部研究として異例に高い。再現性と誠実さの文化ができている。
- 技術実装力がある。Next.jsプロトタイプは一連のフローを動作させており、実装が律速にならない。
- 三条件設計（特にNon-Odor統制条件の存在）は、匂い特有効果と詳細質問一般効果を切り分ける正しい構造を持つ。

### Weaknesses

- 実験刺激（質問文）が存在しない。研究の中核が未着手のまま周辺が完成している。
- 統計設計が未固定で、しかも結果依存の変更を許容する記述が意思決定記録に混入した。

  original_text — 「とりあえずBにして結果を得てからAとしてもいいと考える。」

  source — `docs/project/decisions.md` DEC-011追記（2026-07-15確認）

  note — 結果を見てから主要評価を切り替える行為は、確認的分析を無効化する。これは「柔軟性」ではなく設計の欠陥である。

- 題名・Purpose・Methodsの独立変数が計画書内で一致していない（`docs/research/research-plan-review.md` 矛盾1）。研究質問が本人の中で完全に固定されていない兆候。
- 倫理・同意・データ管理が構想段階のまま。個人的記憶を外部APIへ送る研究であり、ここは後回しにできない。

### Opportunities

- Non-Odor統制がきちんと機能すれば、結果がどちらに出ても解釈可能な論文になる。null resultでも「匂い質問は詳細質問一般を超えない」という報告価値がある。
- 意思決定記録の品質はそのまま論文のMethodsと事前登録文書に転用できる。無駄になっていない。
- 卒業研究の対話設計知見は、大学院案の「センサの必然性」問題に対して「静的演出では代替できない適応的対話」という論拠の種になる。【推測】

### Threats

- 倫理審査の所要期間。機関によっては1〜2か月かかり、9〜10月のパイロットに直撃する。【推測: 所属機関の要否・期間は未確認】
- サンプルサイズの現実。三群一元配置分散分析で中程度の効果（f=0.25）を検出力0.80で検出するには**総N≒157（各群約52名）**、大効果（f=0.40）でも**総N≒63（各群約21名）**が必要（statsmodels FTestAnovaPower, α=.05で算出。G*Powerで要再確認）。学部研究で150名超の募集は非現実的な公算が大きい。【推測: 募集可能人数は記録にない】
- 大学院入試の時期。2027年4月入学なら試験・面接は2026年8〜9月が一般的で、「ガスセンサの必然性が弱い」という未対応の批判を持ったまま面接に入るリスクがある。【推測: 貴学の入試日程は未確認。今週中に確認すべき】
- APIキー漏えいの未処理。失効確認の記録がない。

## 6. Brutally Honest Assessment

**10点満点で: 5点。** 内訳: 研究の方向転換と概念的規律は8点相当。実行は2点相当。テーマ選定から約3か月経過して、実験刺激が1問も確定していない。プロトタイプも文書もこの空白を埋めない。5月10日のレビュー対応は見事だったが、その後の2か月は「決めることを避けるための整理」に費やされた面が大きい。

**最も危険な仮定:** 「設計は流動的なまま、実装と文書化を先に進めてよい」という暗黙の仮定。その具体的な現れが「とりあえずBにして結果を得てからA」であり、これは統計的にはp-hackingの予告に等しい。第二の危険な仮定は「参加者は集まる」。総N≒60〜157という数字に対して、募集計画がゼロである。

**今すぐ捨てるべきアイデア:**
1. DEC-011の「B→A」切り替え案。
2. アーキテクチャ学習目的の書き換え検討（研究終了後にやればよい）。
3. Emotional Connection / System Preferenceの復活余地。
4. 発表資料・説明文の更なる磨き込み。すでに十分であり、限界効用はほぼゼロ。
5. 現時点でのセンサ・TouchDesigner技術検証。入試の論拠構築（文章）だけでよい。

**最も投資価値の高い領域:** 三条件の質問文そのものと、その条件間統制の設計。これが研究の独自性・妥当性・論文のMethodsの全てを決める。次点は早期パイロット。設計上の欠陥は机上レビューではなくパイロットでしか見つからない。

**自覚していないと思われる問題点:**
1. **文書化が先延ばしの形式を取っている。** 意思決定記録・監査・移行文書はどれも高品質だが、この2か月で増えたのは「未決定事項の精密な目録」であり、決定ではない。整理は不安を下げるが、研究を進めるのは決定だけだ。怖い決定（質問文を書き切る、主要指標を1つに絞る）を避けるために、怖くない作業（整理）を選び続けている。
2. **null resultの想定がない。** 最も可能性が高い結果は「三条件間に有意差なし」である。【推測だが、単発の言語的注意操作の効果量は一般に小さい】その場合に卒論として何を主張するか——Manipulation Checkが成立していれば「匂い質問は詳細質問一般を超える効果を持たなかった」は誠実で書ける結論——を今から設計に織り込むべきだ。
3. **動的質問生成が独立変数を汚染していること。** LLMが質問を毎回生成する限り、「質問条件の効果」ではなく「その日そのセッションでLLMが出した質問の効果」を測ることになる。
4. **時間の非対称性。** 卒論執筆（英語）に12月〜1月が丸ごと消える。実質のデータ収集ウィンドウは10月〜11月しかない。今の遅延1週間は、11月の1週間と等価ではなく、はるかに高くつく。

**(3) テストデータと本実験データの分離をコードレベルで強制する。** 仕様凍結前に取得した全データに`spec_version`を記録し、凍結版以外のデータを分析対象から機械的に除外できるようにする。これは13.4作業ルール7の実装である。

## 10.5 残リスク

最大の残リスクはミーティングの遅延である。実装は進むが、⑤〜⑦が決まらない限りパイロットに入れず、10〜11月の収集窓は動かない。ミーティングが1週間以上先なら、議題①〜④だけでも先にメールで送り、非同期で決定を取ることを推奨する。

## 11.3 DEC-027への異議 — このゲートで唯一の重大警告

「卒業研究の内容であり、倫理審査を行うほどの内容ではない」は、**あなた一人が下せる判断ではない。** この研究は、個人の自伝的記憶（センシティブな内容を含み得る）を収集し、第三者の商用API（OpenAI）へ送信し、保存する。人を対象とする研究の審査・届け出の要否を決めるのは所属機関の規程であって、研究者本人の内容評価ではない。記録自体が「所属機関の規則を無効化する法的判断ではない」と正しく留保しているが、その留保が実効性を持つのは、**指導教員が「本件は審査不要」と確認した記録が残ったとき**だけだ。

実害のシナリオも具体的にある。計画書はJSETを発表先候補としている（`docs/research/research-plan-review.md`）。学会発表・論文投稿では倫理的配慮の記載を求められることが多く【推測: JSETの現行要件は要確認】、「審査不要と自分で判断した」は通らない可能性がある。口頭試問でも同じ質問が来る。対処は簡単で、次回ミーティングの議題に「倫理審査・届け出の要否確認」を1行加え、指導教員の回答をDEC-027へ追記するだけだ。コストは5分、放置した場合の代償はデータ収集後の全データ使用不能である。併せて、審査がないからこそ同意文・API送信説明・削除手続き（DEC-019/020）が唯一の倫理的担保になる。この2つの優先度は実質的に上がったと認識すべきだ。
