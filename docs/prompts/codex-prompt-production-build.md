# Codex指示: 本番実験システム基盤層の構築

以下をそのままCodexへ貼り付ける。

---

あなたは卒業研究「匂いに着目した質問がLLM生成物語の評価へ与える影響」の実験システムを本番品質へ引き上げる開発者である。作業前に `docs/project/decisions.md` と `docs/project/prototype-progress.md` を全文読み、DEC番号の制約に従うこと。

## 対象と方針

- 対象コードベース: `expTest1`。新規リポジトリを作らず、現行コードを改修する。DEC-030で検証済みの `lib/followup-generation.ts`・`lib/followup-validation.ts`・`lib/fallback-questions.ts` は挙動を変えない。
- 今回のスコープは**研究仕様に依存しない基盤層のみ**。質問文・尺度文言・ターン数などの内容層は指導教員承認待ちであり、確定させてはならない。
- 未決定値はすべてハードコードせず、バージョン識別子付きの設定ファイルへ外出しし、`DRAFT` と明記する。

## 禁止事項

1. 条件別質問プロンプトの文言変更・「最終化」（DEC-029の未決定項目）
2. 評価項目の正式文言の確定（DEC-010は暫定。項目は4つ: Scene Construction / Narrative Vividness / Affective Atmosphere / Memory-Likeness。Emotional ConnectionとSystem Preferenceは削除する）
3. ターン数の固定値化（設定値とし、既定3はパイロット候補と注記。DEC-029）
4. モデル名の確定（設定値。既定は現行のまま）
5. 実APIを使うテストの無断実行（乾式を既定とし、実APIはフラグ明示時のみ）
6. APIキー等の秘密値のコード・ログ・レポートへの転記（DEC-026）
7. 研究仕様の発明。判断に迷う点は実装せず「要決定事項」としてレポートへ列挙する

## 作業パッケージ（優先順）

### WP1 参加者画面と研究者画面の分離・条件盲検化
- 参加者画面から条件名・条件説明・条件選択UI・現在条件表示を完全に除去する（現状はREADMEの「hidden」と実装が矛盾: `docs/project/prototype-progress.md` 条件盲検化の項）。
- 研究者画面は別ルートに置き、環境変数による簡易認証で保護する。
- 完了条件: 参加者フローの全画面スクリーンショットまたはE2Eテストで条件語が一切表示されないことを機械検証する。

### WP2 ブロック無作為化と割付ログ（DEC-003）
- 使用言語（ja/en）を層としたブロック無作為化を実装。ブロックサイズ・割付比・seedは設定値とし、既定は暫定と明記。
- 割付ログ: 参加者ID、言語、条件、ブロック、seed、割付時刻、アルゴリズム版を保存。`Math.random()` 単純割付を廃止。
- 完了条件: 単体テストで各ブロック内の群サイズ均衡を検証。

### WP3 サーバー側保存とデータ管理（DEC-020方向）
- localStorageを本番経路から除去し、サーバー側DB（SQLite可）へ移行。セッション、対話ログ、生成ログ、評価、割付を保存。
- 参加者IDは無意味な識別子とし、氏名・メール等を保存しない。参加者ID指定の削除スクリプトを用意。
- 完了条件: 保存・読出・削除の統合テスト。

### WP4 回想文生成側の再現性ログ
- `api/generate` にDEC-030と同等のログ（prompt version、実モデル名、temperature、token usage、request ID、生成時刻、失敗・再試行）を実装。追質問側は実装済みなので流用する。

### WP5 評価UIの未回答検出
- 4項目のスライダー初期値送信問題を解消: 未回答状態を明示し、全項目に能動的操作があるまで送信不可。文言は現行のままDRAFT扱い。

### WP6 二言語骨組み（DEC-016）
- 開始時に言語選択、セッション内で言語固定、選択言語を全記録へ保存。UI文字列をja/en辞書へ外出し。日本語を既定。翻訳の質は問わない（後で差し替え）。

### WP7 同意・API送信説明の画面枠
- 初期想起の前に同意画面を挿入。文面は `DRAFT` プレースホルダーとし、同意しない場合は開始不可、いつでも中止できる導線を含める。文面確定はDEC-019で別途行う。

### WP8 テストとエラー処理
- 単体・API・E2E（乾式）のテスト基盤を整備。API失敗時のリトライ・タイムアウト・参加者向けエラー表示・失敗ログを実装。

## 完了報告の形式

- `npm run lint`・`npm run build`・全テストの結果
- WPごとの実装内容、コミットハッシュ、主要ファイルパス（行番号付き）
- 発生した「要決定事項」の一覧（研究者が決めるべき値）
- 変更しなかった検証済みライブラリの一覧と、挙動不変の根拠（テスト）
- 主張には original_text / source / note 形式の引用を付ける
