# Prompt Catalog v0.4.4-draft — 回答状態を優先する質問

Status: DEC-039に基づくmock実装。実APIでの質問品質評価と研究実施の承認は未了。

## 生成方針

ターン別の推奨順序を与えず、初期断片と過去の全質問・回答から対象ごとの既知情報、不明な内容、既質問の内容を読み、次の一問を選ぶ。Standard・Visual・Odorの焦点は引き続き質問可能な範囲を定める。

- 初回も初期断片を使う。条件内の内容が未報告なら、存在を前提にしない広い想起を尋ねられる。
- 具体的な既出内容があれば、まだ聞いていない点を掘り下げる。
- 部分想起では覚えている部分を使い、不明な部分を推測で埋めさせない。
- 曖昧な対象は次の質問に必要な場合だけ確認する。
- 十分に聞いた対象や想起不能な対象からは、条件内の別対象へ移る。
- 条件内で尋ねられる材料がなければ、既存の非想起／材料不足メタデータを使って中立的な出来事質問へ移る。

回答状態の判断は同じ質問生成リクエストの指示内で行う。別の判定APIや正規表現による多状態分類器は追加しない。自動的な非想起検出は補助情報であり、部分想起を含む回答全体の使用禁止にはしない。

## 既存契約と版管理

全条件6問、質問temperature 0.55、初回を含め最大3試行を維持する。DEC-035の必須検証（条件への適合、実験情報の非開示、出力形式、重複）は変更しない。

`turnFunction`は既存enumから実際の質問機能を選ぶ。ターン位置とは対応させない。状態分類用の新しい出力フィールドは追加せず、参照対象は既存の`targetEvidenceId`、中立移行は既存フラグで記録する。これらは対象ごとの状態判断を網羅する監査ログではない。

日本語・英語の質問本文は`prompts/v0.4.4-mock-draft/follow-up.{ja,en}.txt`、条件と非想起検出の補助指示は`follow-up-guidance.{ja,en}.txt`。旧版は比較用に保持する。

質問の生成記録は`prompt-catalog-v0.4.4-mock-draft`、文章生成は従来の`prompt-catalog-v0.4.3-mock-draft`を返す。文章プロンプト、生成規則、CSV保存先とschema v2、Supabaseのスキーマは変更しない。旧結果は書き換えず、同じ保存先にある結果は質問の生成記録の版で区別する。

## 固定フォールバックの範囲

ターン番号による深掘りや5問目以降の自動中立化を外す。最新回答に非想起の自動検出がなく、条件別の広い想起質問が未使用なら、その質問を使う。対象の存在を前提とせず、`targetEvidenceId`はnullとする。

それ以外は中立的な出来事質問の固定バンクから、既存の検証器を通る候補を選ぶ。各候補は内容に対応する`turnFunction`を持つ。有効な候補がなければエラー停止する。

固定フォールバックは意味的な回答状態を判定しない。非想起検出がある場合は`nonRecallTransition`、それ以外に中立へ移る場合は`insufficientEvidenceTransition`を使うが、後者はモデル失敗後に条件内の有効な質問を確保できない場合も含む。`source=fallback`と棄却履歴を併せて解釈し、参加者の材料不足が確認された記録とは扱わない。部分想起も自動検出に一致し得るため、通常生成とフォールバックの中立移行を分けて評価する。

## 検証の範囲

オフラインでは両言語の指示、全履歴の受け渡し、ターン位置によらない質問機能の採用、部分想起の参照、既存の条件違反棄却・3試行・フォールバック・保存契約を確認する。ブラウザfixtureは合成回答のみを扱い、実APIや研究用保存先を使わない。

指示が渡ることや固定候補が検証を通ることは、実モデルが回答状態を正しく判断する証明ではない。意味的な重複、不明な対象の再追及、条件外誘導、中立移行の妥当性、条件別フォールバック率は今後の出力評価対象とする。旧版の評価を新しい質問方針の検証実績として扱わない。

決定の正本: [DEC-039](../project/decisions.md#dec-039-回答状態を優先して次の質問を選ぶ)。
