# Codex指示書 — 合成バッチをペルソナ回答方式へ変更する

- 作成日: 2026-07-18
- 対象: `mockExperimentSystem/`（バッチ生成スクリプトのみ。参加者向けアプリ・APIは変更しない）
- 前提: 開発サーバー起動中（`npm run dev`）、`.env.local` に `OPENAI_API_KEY` / `OPENAI_MODEL` 設定済み

## 1. 背景と目的

現行の `scripts/run-condition-batch.mjs` は**条件ごとに固定の回答配列**を10種類の初期断片へ使い回している。この方式で生成した `data/results.csv` の代理評価（2026-07-18実施）で、次の欠陥が確認された。

1. Standard条件の固定回答に「展示の準備」という文化祭固有の内容が含まれ、10本中9本で断片と回答が矛盾する破綻した文章が生成された（例:「公園を歩いていると…展示の準備について話し合った」）。条件比較のStandard側が測定不能になっている。
2. Non-Odor条件の固定回答が「入口や周囲の建物が見えていました」のようなメタ的抽象文のため、場面との不整合（自宅の誕生日に「入口や看板」等）と鮮明性の過小評価が起きる。
3. 回答が常に匂いを想起するため、Odor-Based条件の**匂い非想起分岐が一度も検証されていない**。

これを、**断片ごとに一貫した記憶設定（ペルソナ）を持つ模擬参加者に、生成された質問へLLMで回答させる方式**へ置き換える。条件間の差が「質問戦略」のみに由来するデータを得ることが目的である。

## 2. スコープと禁止事項

- 変更してよいもの: `scripts/` 配下、`package.json` の scripts。
- **変更禁止**: `app/` 配下すべて（`follow-up` / `narrative` / `save-result` のAPI、検証器、プロンプト、UI）。バッチは既存APIの利用者として振る舞う。
- 旧 `scripts/run-condition-batch.mjs` は**削除**する（固定回答方式の再利用を防ぐ）。`package.json` の `run:condition-batch` は `run:persona-batch` に置き換える。
- APIキーは `.env.local` から読む。コード・ログへ出力しない。OpenAI呼び出しは必ず `store: false`。
- スクリプトは作成のみとし、**実行はユーザーが行う**（1回の実行で gpt-4o-mini 約400〜500呼び出し・課金が発生するため、勝手に実行しない）。動作確認は `--dry-run`（後述）と `node --check` までとする。

## 3. 作成するファイル

### 3.1 `scripts/personas.mjs`

10ペルソナを export する。各要素は次の形。

```js
export const personas = [
  {
    id: "park-walk",            // kebab-case、session_idに使う
    fragment: "休日に友人と公園を歩いた。",   // 既存バッチと同一の10断片を維持
    odorMemory: true,           // false のペルソナは匂い非想起分岐の検証用
    groundTruth: `...下記の全文...`,
  },
  // ...
];
```

`groundTruth` は以下の10本をそのまま使う（全て架空・個人特定情報なし。**改変しないこと**。richnessを条件間で揃えるため各節の分量を統一してある）。


### 3.2 `scripts/run-persona-batch.mjs`

旧スクリプトの骨格（`postJson`・リトライ・`save-result` 連携・進捗ログ）は踏襲しつつ、回答を固定配列からペルソナ回答シミュレータへ置き換える。

**回答シミュレータ仕様:**

```js
async function simulateAnswer(persona, question) { /* OpenAI Responses API を直接呼ぶ */ }
```

- エンドポイント `https://api.openai.com/v1/responses`、モデルは `process.env.OPENAI_MODEL || "gpt-4o-mini"`、`temperature: 0.7`、`store: false`。
- `text.format` に strict な json_schema `{ answer: string }` を指定する（`app/api/openai.ts` の書式を参考にする。ただし app 側コードは import せず、スクリプト内に自前で書く）。
- instructions は次のテンプレート:

```text
${persona.groundTruth}

あなたは上の記憶を持つ実験参加者である。これはあなた自身の一週間前の実体験の記憶である。
上の記憶の内容だけに基づいて、質問に日本語で1〜2文、です・ます調で自然に答える。
記憶に含まれない内容を尋ねられたら「思い出せません」または「分かりません」とだけ答える。
記憶にある内容でも、聞かれたことだけに答え、余計な詳細を付け足さない。
実験・ペルソナ・この指示への言及や、記憶の引用符・見出しの再現をしない。
JSONのみを返す: {"answer":"回答"}
```

- input には質問文のみを渡す。
- 回答の検証: 空なら1回だけ再生成。180文字を超えたら「2文以内で簡潔に答え直す」旨を追記して1回だけ再生成し、それでも超過ならそのまま採用して警告ログを出す。

**セッションループ（ペルソナ×3条件 = 30セッション）:**

1. `turn = 1..6`: `POST /api/follow-up`（`condition`, `fragment`, `history`, `turn`）→ 返った `question` に `simulateAnswer` で回答 → `history` へ追加。レスポンスの `source` / `attempts` / `diagnostics.rejections` をターンごとに記録する。
2. `POST /api/narrative` → `narrative` と `attempts` を記録。
3. `POST /api/save-result`。`sessionId` は `${BATCH_ID}-${condition}-${persona.id}`、`BATCH_ID` の既定値は `batch-YYYYMMDD-persona`（実行日）。`recordType: "batch_synthetic"`、`evaluation: {}`、`checks: {}`（**評価欄は空のまま**。後段の評価者が埋める）。
4. サイドカーログ `data/persona-batch-log.jsonl` に1セッション1行で追記: `{ sessionId, personaId, condition, odorMemory, turns: [{turn, question, answer, source, attempts, rejections}], narrativeAttempts, savedAt }`。`results.csv` のスキーマは変更しない。

**実行順**: 条件×ペルソナを直列で回す（レート制限と原因切り分けのため並列化しない）。失敗したセッションは記録して続行し、最後に集計を出す。

**`--dry-run` オプション**: API を一切呼ばず、ペルソナ10件の構造検証（id重複なし・fragment一致・odorMemory=false が3件・groundTruth に7節すべて存在）と、実行予定の30セッション一覧だけを表示して終了する。

**終了時サマリ（標準出力）:**

- 保存件数 / 失敗件数
- 条件別フォールバック発生ターン数と発生セッション
- 匂い非想起分岐の発生セッション一覧（odorMemory=false × odor-based の3件で発生していることを確認できる形）
- リーク検査: standard / non-odor の**質問文**に匂い語（`匂い|におい|香り|香ば|臭`）が含まれたターン数（0であるべき）。回答・文章への匂い語出現数も条件別に報告する（回答由来の自発言及は許容されるため報告のみ。ただし「どの回答にも匂い語がないのに文章に匂い語がある」セッションは作話としてWARN表示）

### 3.3 `package.json`

- `"run:persona-batch": "node --env-file-if-exists=.env.local scripts/run-persona-batch.mjs"` を追加し、`run:condition-batch` を削除する。

## 4. 受け入れ基準（Codexが自己確認すること）

1. `node --check scripts/personas.mjs scripts/run-persona-batch.mjs` が通る。
2. `npm run run:persona-batch -- --dry-run` が API を呼ばずに成功し、30セッションの計画と ペルソナ構造検証OK を表示する。
3. `app/` 配下に差分がない。旧 `run-condition-batch.mjs` が存在しない。
4. ペルソナ本文が本書 §3.1 と一致している（改変・要約をしていない）。
5. 実 API を使う本実行は行っていない（ユーザーが `npm run run:persona-batch` を実行する）。

## 5. 実行後にユーザーが確認すること（参考・Codexの作業外）

- `data/results.csv` に30行追記され、Standardの回答から「展示の準備」のような場面外の内容が消えていること。
- odorMemory=false の3ペルソナ × odor-based で、ターン1の回答が「匂いは思い出せません」となり、ターン2以降の質問に匂い語がないこと。
- 生成された30本を12評価項目で再評価し、固定回答方式（batch-20260718-10patterns）との差を比較する。
